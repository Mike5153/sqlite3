# SQLite 数据库文件内容结构分析

本文档根据SQLite源码 (`src/btreeInt.h` 等) 分析SQLite数据库文件的完整内容结构。

## 概述

SQLite数据库文件采用**B树**结构来存储数据。文件被分割成固定大小的**页面**（Pages），每个页面可以是以下类型之一：
- **B树页面**（数据页面）
- **自由列表页面**（Freelist pages）
- **溢出页面**（Overflow pages）
- **指针映射页面**（Pointer-map pages）

## 1. 文件结构总览

```
+------------------------+
|  Page 1 (特殊)          |
|  - 文件头 (100字节)     |
|  - 页面头 (8-12字节)    |
|  - 单元指针数组         |
|  - 空闲空间             |
|  - 单元内容区域         |
+------------------------+
|  Page 2                 |
|  - 页面头 (8-12字节)    |
|  - 单元指针数组         |
|  - 空闲空间             |
|  - 单元内容区域         |
+------------------------+
|  Page N                 |
|  ...                    |
+------------------------+
```

## 2. 文件头部 (File Header) - 100字节

文件头仅出现在数据库的第一页的开始。这个头部包含了整个数据库文件的元数据：

| 偏移(Offset) | 大小(字节) | 描述 | 
|------------|---------|------|
| 0 | 16 | 头部字符串：`"SQLite format 3\0"` |
| 16 | 2 | 页面大小（单位：字节）。值为1表示65536 |
| 18 | 1 | 文件格式写版本 |
| 19 | 1 | 文件格式读版本 |
| 20 | 1 | 每个页面末尾未使用的字节数 |
| 21 | 1 | 最大嵌入有效负荷分数（必须为64） |
| 22 | 1 | 最小嵌入有效负荷分数（必须为32） |
| 23 | 1 | 最小叶子有效负荷分数（必须为32） |
| 24 | 4 | 文件更改计数器 |
| 28 | 4 | 数据库的页面大小（以页面为单位） |
| 32 | 4 | 第一个自由列表页面 |
| 36 | 4 | 文件中的自由列表页面数 |
| 40-99 | 60 | 15个4字节的元数据值（传递给更高层） |

### 2.1 元数据值详解 (Offset 40-99)

| 偏移 | 大小 | 名称 | 描述 |
|-----|------|------|------|
| 40 | 4 | Schema Cookie | 模式版本号 |
| 44 | 4 | File Format | 文件格式版本 |
| 48 | 4 | Cache Size | 页面缓存大小 |
| 52 | 4 | Largest Root-Page | 最大根页面（自动/增量真空） |
| 56 | 4 | Text Encoding | 文本编码：1=UTF-8, 2=UTF-16LE, 3=UTF-16BE |
| 60 | 4 | User Version | 用户版本 |
| 64 | 4 | Incremental Vacuum | 增量真空模式 |
| 68 | 4 | Application-ID | 应用程序ID |
| 72 | 20 | 未使用 | 保留空间 |
| 92 | 4 | Version-Valid-For | 版本有效性检查 |
| 96 | 4 | SQLITE_VERSION_NUMBER | SQLite版本号 |

## 3. 页面结构 (Page Structure)

每个数据库页面都包含三个主要区域：

### 3.1 页面头 (Page Header)

页面头的大小取决于页面类型：
- **叶子页面**：8字节
- **内部节点**：12字节

| 偏移(相对页面起始) | 大小 | 描述 |
|-----------------|------|------|
| 0* | 1 | 标志位（Page Type Flags） |
| 1 | 2 | 第一个自由块的字节偏移 |
| 3 | 2 | 页面上的单元数 |
| 5 | 2 | 单元内容区域的第一个字节 |
| 7 | 1 | 碎片化的自由字节数 |
| 8** | 4 | 右子页面指针（仅内部节点） |

*对于Page 1，该偏移是相对于100字节文件头之后的
**仅对内部节点存在

### 3.2 页面类型标志 (Page Type Flags)

页面的第一个字节包含标志位，用OR操作组合：

| 值 | 标志名 | 描述 |
|----|-------|------|
| 0x01 | PTF_INTKEY | 表B树（整数键） |
| 0x02 | PTF_ZERODATA | 零数据页面 |
| 0x04 | PTF_LEAFDATA | 叶子数据页面 |
| 0x08 | PTF_LEAF | 叶子页面 |

例如：
- `0x0D` (0x01 | 0x04 | 0x08) = 带整数键的叶子数据页面
- `0x05` (0x01 | 0x04) = 带整数键的内部节点

## 4. 单元指针数组 (Cell Pointer Array)

单元指针数组紧接着页面头。数组包含指向单元内容的2字节偏移量：

```
页面结构示例：
+------------------+
| Page Header      | (8或12字节)
+------------------+
| Cell Pointer[0]  | (2字节)
| Cell Pointer[1]  | (2字节)
| ...              |
| Cell Pointer[n]  | (2字节)
+------------------+
| 未分配的空间      |
+------------------+
| Cell Content 2   | (从页面末尾向上增长)
| Cell Content 1   |
| Cell Content 0   |
+------------------+
```

**重要特性：**
- 单元指针按**排序顺序**出现
- 指针从页面头向下增长
- 单元内容从页面末尾向上增长

## 5. 单元 (Cell) 结构

### 5.1 表B树单元 (INTKEY表)

对于使用整数键的表：

```
SIZE    DESCRIPTION
----    -----------
4       左子页面指针（仅内部节点）
var     数据字节数
var     键值（实际上是ROWID，存储在大小字段中，不在有效负荷中）
*       有效负荷（实际数据）
4       溢出链的第一页（仅当有溢出时存在）
```

### 5.2 索引B树单元 (BLOBKEY索引)

对于使用任意键的索引或无ROWID表：

```
SIZE    DESCRIPTION
----    -----------
4       左子页面指针（仅内部节点）
var     键字节数
*       键内容（有效负荷）
```

### 5.3 变长整数编码 (Varint)

SQLite使用变长整数编码来节省空间。整数由1-9字节表示：

```
编码示例：
0x00 -> 0x00000000
0x7f -> 0x0000007f
0x81 0x00 -> 0x00000080
0x82 0x00 -> 0x00000100
0x80 0x7f -> 0x0000007f
0x81 0x91 0xd1 0xac 0x78 -> 0x12345678
```

**编码规则：**
- 第1-8字节：低7位作为数据，第8位作为"继续"标志
- 第9字节：所有8位作为数据
- 最高有效字节出现在最前面

## 6. 溢出页面 (Overflow Pages)

当单元的有效负荷超过页面的最大嵌入有效负荷分数时，多余的数据存储在溢出页面中：

### 溢出页面结构：

```
SIZE    DESCRIPTION
----    -----------
4       下一个溢出页面的页面号
*       数据（最后一页可能不满）
```

**链接机制：**
- 第一个溢出页的页面号存储在单元的"溢出链第一页"字段中
- 每个溢出页都包含指向下一个页面的指针（或0表示末尾）
- 除最后一页外，每个页面都被填满（页面大小 - 4字节）

## 7. 自由列表页面 (Freelist Pages)

自由列表用于跟踪未使用的页面。包括两种类型的页面：

### 7.1 自由列表树干页面 (Trunk Page)

```
SIZE    DESCRIPTION
----    -----------
4       下一个树干页面的页面号
4       此页面上的叶子指针数量
*       零个或多个叶子页面的页面号
```

### 7.2 自由列表叶子页面 (Leaf Page)

内容未指定，可以是任何数据。这些页面在被重新使用时会被覆盖。

## 8. 空闲空间管理 (Free Space Management)

### 8.1 自由块链表 (Freeblocks)

单元内容区域内未使用的空间被组织成链表：

```
SIZE    DESCRIPTION
----    -----------
2       下一个自由块的字节偏移
2       此自由块中的字节数
```

**约束条件：**
- 每个自由块至少4字节
- 自由块以递增顺序出现
- 3字节或更少的未使用空间称为"碎片"

## 9. B树页面中的有效负荷分数

SQLite使用"有效负荷分数"来控制单元在页面上的分布：

- **最大嵌入有效负荷分数** (默认64/255): 单个单元可以占用的最大页面使用百分比
- **最小嵌入有效负荷分数** (默认32/255): 单元在触发溢出前必须保持的最小大小
- **最小叶子有效负荷分数** (默认32/255): 仅适用于LEAFDATA树的叶子节点

这些分数确保：
- 至少4个单元可以适配一个页面
- 防止某个大单元占据整个页面

## 10. 事务和日志

SQLite支持多种日志模式：

### 10.1 日志模式

| 模式 | 常量 | 描述 |
|-----|------|------|
| DELETE | 0 | 通过删除日志文件提交 |
| PERSIST | 1 | 通过将日志头清零提交 |
| OFF | 2 | 不使用日志 |
| TRUNCATE | 3 | 通过截断日志提交 |
| MEMORY | 4 | 使用内存中的日志文件 |
| WAL | 5 | 使用写前日志 |

### 10.2 文件更改计数器

文件头中的文件更改计数器在数据库每次修改时递增。其他进程可以通过检查此计数器来确定缓存是否有效。

## 11. 数据库页面限制

| 参数 | 最大值 | 默认值 |
|-----|-------|--------|
| 页面大小 (Page Size) | 65536字节 | 4096字节 |
| 页面数 (Page Count) | 4294967294 | 取决于文件大小 |
| 单元大小 (Cell Size) | pageSize - 8 | 取决于数据 |
| 单个页面的单元数 | (pageSize-8)/6 | 取决于数据 |

## 12. 内存中的页面表示 (MemPage结构)

SQLite在内存中使用`MemPage`结构来表示加载的页面，包含解析后的页面信息：

```c
struct MemPage {
  u8 isInit;           /* 初始化标志 */
  u8 intKey;           /* 整数键表 */
  u8 intKeyLeaf;       /* 整数键叶子 */
  Pgno pgno;           /* 页面号 */
  u8 leaf;             /* 叶子页面标志 */
  u8 hdrOffset;        /* 页面1为100，其他为0 */
  u8 childPtrSize;     /* 0=叶子, 4=内部节点 */
  u16 maxLocal;        /* 最大本地有效负荷 */
  u16 minLocal;        /* 最小本地有效负荷 */
  u16 cellOffset;      /* 第一个单元指针的索引 */
  u16 nCell;           /* 页面上的单元数 */
  u8 *aData;           /* 页面数据指针 */
  /* ... 其他字段 ... */
};
```

## 14. 关键特性总结

1. **可变大小的页面**：512-65536字节
2. **高效的空间利用**：通过自由块链表和碎片跟踪
3. **灵活的数据类型**：通过变长整数编码
4. **事务支持**：通过日志和多种提交模式
5. **自动真空**：释放未使用的页面回自由列表
6. **缓存管理**：通过有效负荷分数优化页面内容分布
